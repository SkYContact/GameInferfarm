# 黑白棋上 inferfarm 尖刺报告（2026-09-22，GO/NO-GO 数据）

## 结论：PG 路线 GO（rollout 5-6×），ES 留 torch（架构不适配），全量重做改为混合架构

## 实测数字（6 组×2 银行，w14，stagger=0；批宽扫描追加 2026-09-22 下午）

| 配置 | 局/s | vs torch ES 957 |
|---|---|---|
| torch ES（B=1024，对照） | 957 | 1× |
| torch PG rollout（B=256，对照） | 330-400 | 0.35× |
| farm fb16：192 槽（gomoku 冠军配置照搬），256 链 | 2069-2139 | 2.2× |
| farm fb64：768 槽，1024 链 | **12,188** | **12.7×** |
| farm fb128：1536 槽，2048 链 | **28,813** | **30×** |

- fb128 决策吞吐 87 万决策/s（991,984 / 1.14s）；胜率 82.5-82.6% 口径全程稳定、推理故障 0
- **瓶颈结构公式**：农场吞吐 ≈ 在飞槽位数 ÷（每局 30 决策 × 服务延迟）——fb16 时被
  192 槽锁死（94% 顶格），加宽银行即线性解锁；torch 则是"每 ply 固定开销 ÷ 批量"，
  B=1024 摊得不错所以只差 2.2×。跨批宽指纹不同批（ORT 按批形选 kernel，末位差
  翻转近平局 argmax，与 CUDA/CPU 差同类，预期内）
- **重做经济学改写**：PG 臂 102.4 万局 rollout 在 fb128 下 ≈ **36 秒**——矩阵彻底变为
  更新侧瓶颈；ES 留 torch（957/s，18 分钟/臂）反而成了最慢的一环

## 正确性验证（三层）

1. **规则属性测试**：38,400 组（300 随机盘×2 色×64 格）合法性与翻子集 vs 09 的
   legal_map_shift/flips_for_action 两套实现**零分歧**；
2. **ONNX 导出**：与 torch 前向逐位同（max|diff|=0，CPU EP）；
3. **全协议对拍**：Python 同协议复算 1280 局 vs C++ 腿：胜率 82.3% vs 82.1%、
   决策 38771 vs 38767、逐局一致 99.8%（3/1280 局分歧=CUDA/CPU 浮点末位差
   翻转近平局 argmax，属预期）；**跨组数指纹全同**（并行度不变棋）。

## 过程中捉掉的两只真 bug（对拍纪律的又一次回本）

1. **栈溢出 fast-fail（0xC0000409）**：射线中间子数组 path[6] 装不下 7 个——
   边格出发整列对手子时越界写。path[7]+flips[64] 修复；
2. **子数计数 bug（冤杀主因）**：`discs += 1 + 翻子数` 把翻子当新增子（翻子=变色
   不添子），3 倍速假满盘 → 棋盘 28 子/剩 36 空格就被判终局 → 模型被冤杀到 13%
   胜率、每局只走 11.8 手。09 环境用 0/1 平面和（board.sum()）天然免疫。
   症状链：C++/Python 同错（同源理解）+ 平面对调无效 + 规则属性测试全绿 →
   计数器单独背锅。修复后 82%、30.3 手/局，全对上。

## 全量重做的工程路线（混合架构）

- **PG 臂（GO）**：farm 跑 rollout（需改造：ApplyResult 从 argmax 改温度采样+
  记录 (obs, action, logprob) 轨迹落盘）→ torch 读轨迹做更新 → **TRT refit 换心**
  （ORT 后端无 refit API，必须走 build-trt；工具链 refit_blob.py/refit_probe 现成）。
  预估臂时长 52-63 分钟 → ~15-20 分钟；
- **ES 臂（留 torch）**：128 个体各自权重 vs 银行"一模型"架构冲突，逐个体 refit
  串行化后净收益估 ~1.5×，不值；ES 957 局/s + 18 分钟/臂本来就不慢；
- **BC/CNN/评估**：BC 纯监督不受益；评估（vs 锚点池）反而天然适配 farm
  （锚点=固定模型，一套配置跑 Elo 天梯全套对局，4× 提速）；
- **多种子愿景**：PG 臂提速后 7 臂 ×3 种子 ≈ 一晚跑完，杀掉"单种子"局限。
