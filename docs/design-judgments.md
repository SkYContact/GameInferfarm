# 设计判决（每条都有实测 why——勿凭直觉推翻）

> 来源：YGO 产线两夜 42→317-368 局/s（7.5-8.7×）的全部弯路沉淀。
> 环境：9955HX 16C/32T + 5070Ti Laptop。完整账本见 D:/ygo/.zcode/memory/
> inferfarm-handover.md §三 与 es-proving-ground-batch.md。

## 1. 到达层羊群：错峰是相位工程，不是 OS 问题
256 局同步起跑=灾难（69 局/s）。stagger 错峰=相位去同步；**fiber 下照样存在**
（不是 OS 抢占问题）。10ms 甜点；短作业 25ms 反噬。本库：`stagger_ms`（默认 10）。

## 2. SMT 是负资产
本负载 K=32/24 都比 K=16 差（lua 分支密缓存敏感）。工人默认=物理核
（hardware_concurrency/2）。**勿超物理核。**

## 3. 窗的真相：Windows 定时量子 ≈1ms
timeBeginPeriod(1) 下 cv 定时量子仍 ≈1ms——老路径"window 0.1" 实为 1ms。
银行调度台用 µs 精钟**忠实执行 0.1ms 会批量饿死 10×**。floor=0.2ms 实测最优
（0.15→127 / **0.2→129.6** / 0.25→127.6 / 0.3→124.6 / 1.0→100.4=旧路径平价点）。
本库：`window_floor`（默认 0.2，env FARM_BANK_WINDOW_FLOOR）。

## 4. 独车税：低负载下银行比内联慢
solo（单局）下银行慢 65%——每决策 1-2 个**线程唤醒量子**（工人睡了没人暖场）。
多线程满载整类成本消失（复活 0.12ms 实测）。纤程切换本身 ns 级。
混合规则（低负载内联发车+自旋）已设计未建（路线图项）。

## 5. 批的物理：每批固定门票
图回放每批 ~0.4ms 固定门票（kernel 发射+权重流 VRAM）**与行数无关**。
微批=为同一张图付全款；攒批大=每人多等窗（串行链付款）。银行=异步多批在飞
把门票重叠掉（gpu_flight 可 >100%）。

## 6. 调度台单线程
发车+收货+还池一人全包（完成序=投递序天然确定）。万批/s 量级（EPYC）时需分家
——已知扩容点，现在不分。

## 7. 图与地址一夫一妻
图回放烧死输入地址 → 每家银行一张专属预捕获图。真 free 银行会导致重新捕图
=灾难，所以"销毁"=归还预分配池（线性生命周期）。启动期图地址烧死小实验
（ProbeGraph）不过=拒绝银行制——字节安全性不赌。

## 8. 先占在途再领号（游标制）
领号=先 `inflight++` 占名额再 `cursor.fetch_add`——占额者必完工 ⇒ close-drain
等 inflight==0 时游标已终态，有效行=前缀连续 [0,n)。迟来残号由 state 复检拒绝，
虚增量在发车侧按作废槽跳过，账号自洽。

## 9. drain 有界：不写超时不写迁移
组装=同步纯计算无挂起点（GameAdapter 契约 1），在途写手必在几十 µs 完工。
close-drain 自旋等归零即可——超时/迁移路径是复杂度负债，明确不写。

## 10. 满座自驱发车
"满=人人写完"由 +1-先于-领号的构造成立。最后完笔者发现（游标满 && 在途归零）
就地发车，不等 timer 不经他人手。CAS 保证一家银行只发一次。

## 11. 只拷前 n 行
n>7/8·slots 走整块，否则逐输入前缀。第 n..slots 行图照读显存上批旧数据——
**行独立前提**下无害，每发车省 5.4MB→n×行宽 的 PCIe。

## 12. ORT 与 TRT 的分界（2026-09-22 追加）
- 调度/拷贝/攒批层收益**后端无关**（fiber 唤醒税、直写槽、批摊薄）——ORT 全额吃。
- 提交层（图合并 WDDM 提交、邮箱盖章去围栏）TRT 独有；ORT 有 enable_cuda_graph
  但绑线程（PerThreadContext 铁律）——银行会话全生命周期钉在调度台线程即合规。
- ORT 不暴露内部流 → 收割退回整设备同步（围栏税 ~0.4-0.5ms/批落在调度台线程，
  GPU 侧多批仍并行）。不赌 ORT 流序是纪律。
- refit 换心 TRT 独有；ORT 候选迭代=每腿重载会话（秒级）——演化场景选 TRT。
- 缺的实测点：**"ORT+银行制"的吞吐数**（账本里只有 ORT+线程 100 局/s 与
  TRT+银行 317-368 局/s 两端）——三后端接口就位后 A/B 交替 ≥4 腿补上。

## 13. 推理缓存：键=组装行字节+权重代次（2026-09-22 追加，KataGo 吸收）
同输入行必同输出（逐位）是行独立契约的直接推论——推理结果可以缓存。键=
本槽**全部输入行的组装字节**（含 Claim 清零后未写区的零——零基组装的一部分）
的 128 位哈希 + 权重代次 gen（换心成功即 ++，旧代永不再命中，不清表——直接
索引自会覆写）。值=逐输出 (名字, n, fp32) 的**n 全宽逐字节重放**（请求即消费
契约：语义不弱于收割路径的 min(w,n) 截断）。

结构判决（KataGo NNCacheTable 同款）：2^log2_cap 直接索引表，单槽单条目，
**碰撞即逐出**（自博弈状态访问近似均匀，无链无 LRU 是最优性价比）；MutexPool
256 把条锁，锁内只做 shared_ptr 拷贝/交换（make_shared/memcpy 全在锁外）；
命中出借 `shared_ptr<const>`——并发逐出后调用方手里的指针仍活着。

命中路径与银行协议的接缝：`Abandon` 弃槽（作废槽+完工照减+发车跳过——本就
是协议原生路径，非新语义）。**对价诚实**：零拷贝直写架构下命中仍付 Claim 清零
+组装 µs 级 CPU 税（行先写进槽才能算哈希）——KataGo 客户端自持行缓冲，缓存
检查在进队列前免费；我们不引进那次拷贝（"同进程内拷来拷去是不对的"）来省这
点税。布局门：条目输出面（名字+n 逐位）与本次申报不符=视同未命中——正确性
无条件。fiber 安全：条锁临界区无挂起点（与 tally 锁同论证）。

实测（farm_test G7）：五子棋 8 局冷腿命中 6.7%（空盘首决策跨局重放）；同农场
二腿（全部状态已见过）**100% 命中、430 局/s vs 关缓存 153 局/s**，指纹与
推理路径逐位同。

## 14. KataGo 互证与不吸收清单（2026-09-22 追加）
- **互证**：KataGo 注释原文承认 fixed-shape 后端把每批补齐到 maxBatchSize、
  调小发送行数只浪费补齐行、要真跑小批须重建求值器——与判决"fb 钉死+行独立
  +垃圾行无害+前缀拷贝"是同一条路的两端独立发现。它无 CUDA Graph/邮箱不是
  落后：主力跑 Linux 无 WDDM 提交税——图+邮箱是 Windows 平台判决，非过度设计。
- **防退化备忘**：后处理（softmax/遮罩/视角翻）永远在唤醒后的客户端做，
  收割线程只搬裸输出（KataGo 同款：server 只填 buf，client 醒来自算）。
- **不吸收**：MCTS 层的虚拟损失/树复用/子树复用=搜索算法=乘客（适配器）的
  事，框架不应知道；8 对称随机化=游戏特定，适配器在 AssembleInto 里自己
  确定性做；KataGo 的单跳拷贝（客户端行缓冲→服务器批缓冲）——我们直写槽
  零拷贝严格更优，不回头。
- **已同构**：多服务器线程拉模型（waitPopUpToN 有多少发多少）≙ 满座/窗发车
  双通道；gpuIdxByServerThread（线程↔卡钉扎）≙ 多银行→多 GPU 的推广（路标）；
  fp16 全后端谱系（我们 int8/fp32 之间的空档=路标）。

**适用面边界（实测，勿省略负结果）**：缓存经济学后端相关。CPU 后端批计算按
**领号前缀**行数算（弃槽行照算垃圾），且命中纤维不挂起会对领号/池机器形成
踩踏：玩具尺度 512 局 A/B，53% 命中反而 1079 vs 2709 局/s（2.4× 慢；银行
cycle 0.17→0.79ms，批数 ×2.6）——扎实负结果。100% 命中（热缓存腿）则
430 vs 153 局/s（2.8× 快，省的是 srv-lat 往返）——CPU 后端高命中才赚。
GPU 后端（trt/ort 图会话）批形状钉死 fb 行恒执行——垃圾行免费，命中省
收割/往返/H2D，机械上是纯赢；但玩具尺度 ORT 实测两对 A/B 方向相反
（573/633 与 651/605 局/s）——±10% 效应淹没在 ±13% 跑间噪声里，**不可判**，
真判决待 YGO 尺度（fb=64 大模型+GPU 忙时往返才是缓存的主战场）。默认关，
GPU 后端建议开着扫（指纹不变性由 G7 保，性能只有上行空间）。Abandon 不
Notify（inflight-- 只被 drain 自旋等待；全弃批关舱由窗闹钟兜底）——缓存命中
高频路径的唤醒风暴教训（实测该 Notify 非主因，摘除仍正确：协议上无人需要它）。

## 15. 多设备=设备挂银行+链钉扎（2026-09-22，KataGo gpuIdxByServerThread 同构）
一组=一套后端实例+模型配置+银行数；组池/组轮转/组窗/组等待全分列（他组轮转
不惊醒本组写手）；链 c 钉扎到组 c%n_groups——**异构设备的跨跑逐位钥匙**：
每链恒用同组=同后端=同位。同构多卡（2× 同型号 NVIDIA）逐位门天然保；异构
（NVIDIA+AMD）靠钉扎保"同配置重跑逐位同"（实测：cuda+dml 三跑指纹全同）。
推理缓存键掺组号（异构同字节行输出逐位可异，条目不跨组共享）。

实测（5070Ti Laptop + 610M 核显，本机）：双 ORT 同进程共存（CUDA 1.30 构建
+ DML 1.24 构建）；异构 64 局 315/s，指纹三跑全同；**观察级**：该 fp32 MLP
工件上 CUDA/DML/TRT 三家逐位一致（指纹同单设备腿——不保证推广到大模型，
只证明协议面通）。610M=验证台非算力（66K rows/s 玩具，DML 调度开销绑定）。

三条血律（本日新增，坑目录同）：
1. **双 ORT 改名律**：CUDA 构建与 DML 构建是两颗同名 onnxruntime.dll——
   Windows 按基名去重回柄，第二颗必须拷贝为 %TEMP%\inferfarm_ort_<n>.dll
   再装（依赖走 PATH 前插）。ORT 后端全面实例化：api/env/dll 全下沉成员，
   一实例=一运行时=一设备组。
2. **DML 输入重绑血律**：iob 预绑的 CPU 输入被 DML EP 忽略（读恒零设备缓冲
   ——probe"两图案不可分辨"即此症），输出预绑却正常回传。判决：每次 Run 前
   用新鲜 CPU OrtValue 重绑输入（python numpy 路同款 staging）。DML 路线=
   宿主绑定+同步 Run：无图无围栏无 cudart，probe 门口实验兜底同步假设。
3. **多组化改造残留案**：公共包装函数（BankScheduler::InputRow）残留旧单组
   成员 impl_->be（新路径从未赋值）→ 空指针虚调用段错误。教训：多组化时
   成员删除优于保留（编译器替你找全用点）。

**share 配比与批密度稀释定律（2026-09-22 追加实测）**：`DeviceConfig.share`
链分配权重（平滑加权轮询，nginx 同款；缺省 1=均分，两组时≡c%n_groups 老
行为；0=该组不接链）。**异构卡速差大时按算力配比**（主卡 share=4 核显
share=1 之类）——链号确定性映射，逐位门不破。

分组代价的真相（诊断定谳，勿凭直觉）：
- **批密度稀释**（主因）：链被分组切薄 ⇒ 每组到达流变稀 ⇒ 每批行数下降 ⇒
  同量决策摊 2× 批开销。实测 32 局/8 链：单卡 533 局/s，**双 CUDA 同构组**
  320 局/s（同后端同卡也慢——排除"核显慢"解释），share=0 空转组 457 局/s
  （排除"调度台共享"解释）。
- **大尺度反转**：512 局/32 链（每组 16 链=到达流够稠）：均分异构 **1113
  局/s > 单卡 654**——两组=两条并行填充管线（单组同时只有一家填充银行）。
- 定律：**链稀=批稀=分组亏；链稠=双管线=分组赚**。share 是用户旋钮；真正
  的算力场景（YGO 级模型）610M 类卡按 share 压到象征性或 0。每组独立调度
  台（DML 同步提交的队头阻塞，贡献 ~0.02s/32局，次要）留路标。

## 16. population 路由（演化负载，2026-09-22，spike_othello 需求）
ES 种群=同架构异权重多模型同时推理。判决：**逐行权重路由**（需求方候选 1）
——模型图自带 `pop [P, flat_w]`（种群权重平面，**图输入非常量**）+ `mid [slots]`
（每行个体号），图内 Gather+bmm 一行用自己那套权重。三处豁免+一 API：
Claim 清零跳过 pop 面；缓存哈希跳过 pop（**代次 gen 管失效——refit 代次机制
原样复用**）；cuda SubmitBatch 脏旗全量 H2D（代间零拷贝，dml/cpu 直读宿主=
零拷贝）；`Farm::SetPopulation(host)` 写全部银行+代次++。适配器零新机制
（mid=普通小输入，进哈希/前缀拷/清零全现成）。锚点对手=pop 面多占行，
"双模型在飞"自动成立；PG 换心=SetPopulation 毫秒级（替代 TRT refit，此类
模型不需要 refit 了）。dim0=P≠slots 合法（population 输入豁免批形校验，
arena 按总量）。

**实测（黑白棋 41k 参数 MLP，P=128，1024 局/代）**：真模型路由腿（fb128×
12 银行，1024 链全并发）**0.52-0.54s/代 vs torch 参考实现 1.07s = 2.0×**
（需求方门槛"≤1s=追平"达成；"<0.3s=显著超越"未达——瓶颈=routed 图自身
的 gather+bmm 每行 164KB 权重流量，持续 60K 决策/s 与 torch 同形状同量级，
进一步提速属图侧[fp16 pop 面/算子融合]非框架侧）。指纹跨银行数全同（2 银行
≡12 银行逐位）+ 逐代变（SetPopulation 生效）。G9 门四件套全绿（均匀 pop=
单模型逐位同/重跑同/换代必变/代次失效端到端不串代）。
cpu 后端路由模式（decl.pop_p>0 自动追加 pop/mid；flat 布局=BuildMlpWeights
生成序，CpuBuildMlpFlat 公开序列化器）；TRT fail fast（前缀拷协议未覆盖
population 面，路由图走 ort/cpu）。

**网格路由与死行协议（2026-09-22 深夜追加，网格图 v2.2）**：把"权重迁就行"
翻转为"行迁就权重"——行散射进 [P,8] 网格，pop 平面原地切片当 bmm 权重
（零 Gather 零物化，权重复用 1×→8×，matvec→小 GEMM）。S=P×8=1024 钉批
（一批=全体一步=网格满的前提）。**死行协议**（活性非确定性的根治）：批可
部分填充（n<S），未领槽位留旧 mid——陈旧行参与图内散射会破坏 (p,j) 唯一
性（溢出/碰撞经 ScatterND 原子写污染新鲜行）。两件套：①后端 SubmitBatch
把路由键（1-D i64 非 population 输入）尾段 [n,S) 毒化 -1（cuda 前缀路径另
补设备侧拷贝；dml 直读宿主）；②图 v2.2 设死路由块（mid<0 或越界 → 第 P+1
个体块，j%8 容死行互撞；权重面 Concat 零行补位，死行输出恒 0 不被收割）。
**实测**：同配置×3 + 2/6/12 银行跨并行度指纹全同（且=gather 路由的指纹——
两种图在博弈层逐局一致）；**0.115-0.138s/代 = torch 1.07s 的 8×**（2 银行
即最优：1024 行大批无需多银行轮转，12 银行反 0.27s）。已知限制：网格图含
CPU 回落形状算子 → ORT CUDA 图捕获不兼容（--no-graph 跑）；子代理报的
~20MB/前向 权重补行拷贝可改激活侧补零（优化余地）。

**批密度稀释定律的操作判据（2026-09-22 回接方反例定谳）**：拆组前先看
**rows/batch**——接近满（如五子棋 CNN 的 8.0/8=100%）=填充道堵死形态，GPU
算得动喂不满，第二填充道纯赚（2.8×）；**个位数稀批**（如 YGO 产线 3-6/64，
0.2ms 窗限+gpu_flight 79-139% 已重叠）=到达率绑定形态，瓶颈在上游
（lua/CPU+每决策时延），拆组=到达率减半批更稀+双会话双权重流，**净负**。
定律在第二游戏上验证：预测与实测方向一致（YGO 多组提案被产线读数否决）。
